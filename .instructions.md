# Open Shooting Gallery - Arduino Controller

## Project Overview
This is an Arduino-based controller for a shooting gallery system with 12 targets. The controller receives commands from a server and sends status updates back via serial communication using a custom 32-bit protocol system.

## Communication Protocols

### Protocol Structure
All protocols use **32-bit words** (except LIGHTING which uses 96 bits / 3 words).

**Standard bit ordering**: MSB (most significant bit) on the left, LSB on the right.

**Visual format**: Each protocol is documented with pipe characters (|) and arrows (↑) for alignment. The format `00 00 00 00` indicates bits set to 0 (reserved/unused), while `__ __ __ __` indicates configurable bits.

## RX Protocols (Received from Server)

### 1. GENERAL Protocol (1x32 bits)
**Purpose**: Main game control word, processed FIRST
**File**: `general_protocol_rx`

#### Bit Layout
- **Bits 31-28** (4 bits): **PROTOCOL ID**
  - `0x0` = general (this protocol)
  - `0x1` = target
  - `0x2` = lighting
  - `0x6` = return

- **Bits 27-24** (4 bits): **MODE**
  - `0x0` = idle
  - `0x1` = target reset (bring servos to 0°)
  - `0x2` = run game
  - `0x3` = run debug (optional target defined in next field)

- **Bits 23-20** (4 bits): **TARGET ID**
  - `0-12` (0x0 to 0xC) = specific target
  - `13` (0xD) = all targets
  - `15` (0xF) = controller itself

- **Bits 19-16** (4 bits): **RESERVED**

- **Bits 15-8** (8 bits): **GAME RUN TIME**
  - In 10-second increments
  - Example: `0x01` = 10s, `0x0F` = 150s (2m30s)

- **Bits 7-0** (8 bits): **RESERVED**

---

### 2. TARGET Protocol (1x32 bits)
**Purpose**: Per-target control and configuration
**File**: `target_protocol_rx`
**Processing**: Mandatory to send with general sequence, processed THIRD (at minimum)
**Multiple**: Can send up to 12 words (one per target), each with unique ID

#### Bit Layout
- **Bits 31-28** (4 bits): **PROTOCOL ID** = `0x1` (target)

- **Bits 27-24** (4 bits): **MODE**
  - `0x0` = halt target
  - `0x1` = start moving target (continuous until halted)
  - `0x2` = one-time move to specific % hidden (see TARGET VISIBILITY)

- **Bits 23-20** (4 bits): **TARGET ID**
  - `0-11` (0x0 to 0xB) = specific target (12 total)
  - `12` (0xC) = all targets

- **Bits 19-18** (2 bits): **TARGET MOVEMENT SPEED**
  - `0-3` representing 25%/50%/75%/100%
  - Used for transitions, moves, and jukes

- **Bits 17-16** (2 bits): **RESERVED**

- **Bits 15-12** (4 bits): **TIME BETWEEN TARGET MOVE CYCLES**
  - In seconds (0-15s between cycles)
  - Used for hold (hidden), exposed (visible), and jukes

- **Bits 11-8** (4 bits): **TARGET JUKE %**
  - In 10% increments
  - Example: `0x3` = 30% of move cycles are jukes

- **Bits 7-4** (4 bits): **TARGET RANDOM SPEED CHANGE %**
  - In 10% increments
  - Example: `0x3` = 30% chance
  - Randomizes speed 0-3 each cycle

- **Bits 3-0** (4 bits): **TARGET VISIBILITY**
  - % hidden in 10% increments
  - `0` = visible, `10` (0xA) = 100% hidden
  - Example: `0x3` = 30% hidden

---

### 3. LIGHTING Protocol (3x32 bits = 96 bits)
**Purpose**: Custom lighting controls for target LEDs and arena lighting
**File**: `lighting_protocol_rx`

#### WORD 1 - Control & Brightness (Bits 95-64)
- **Bits 95-92** (4 bits): **PROTOCOL ID** = `0x2` (lighting)

- **Bits 91-88** (4 bits): **MODE**
  - `0x0` = turn lighting off
  - `0x1` = turn lighting on

- **Bits 87-84** (4 bits): **TARGET ID**
  - `0-11` (0x0 to 0xB) = individual target
  - `12` (0xC) = all targets via SPI
  - `13` (0xD) = arena lighting (relay controlled)
  - `15` (0xF) = ALL lighting

- **Bits 83-80** (4 bits): **RESERVED**

- **Bits 79-72** (8 bits): **BRIGHTNESS**
  - Decimal percentage (1-100)
  - Example: `0x64` (100 decimal) = 100%

- **Bits 71-64** (8 bits): **RESERVED**

#### WORD 2 - LED Range (Bits 63-32)
- **Bits 63-48** (16 bits): **START LED RANGE**
  - Position within target's LED segment (0-511 per target)
  - Only for SPI target LED strips
  - Total system: 8960 addressable LEDs (0-511 per target × 12 targets)

- **Bits 47-32** (16 bits): **END LED RANGE**
  - End position within target's LED segment
  - Defines range for color settings

#### WORD 3 - RGBW Color (Bits 31-0)
- **Bits 31-24** (8 bits): **R (RED)** - 0-255
- **Bits 23-16** (8 bits): **G (GREEN)** - 0-255
- **Bits 15-8** (8 bits): **B (BLUE)** - 0-255
- **Bits 7-0** (8 bits): **W (WHITE)** - 0-255

## TX Protocol (Sent to Server)

### 4. RETURN Protocol (1x32 bits)
**Purpose**: Send game state updates to server (target hits, acknowledgements, errors)
**File**: `return_protocol_tx`
**Requirement**: Server must be listening over serial

#### Bit Layout
- **Bits 31-28** (4 bits): **PROTOCOL ID** = `0x6` (return)

- **Bits 27-24** (4 bits): **MODE**
  - `0x0` = idle
  - `0x1` = acknowledgement of target reset
  - `0x2` = acknowledgement of run game (round active)
  - `0x3` = acknowledgement of run debug
  - `0x4` = target hit
  - `0x5` = end of game signal
  - `0x9` = to stdout (debugging)
  - `0xA` = error

- **Bits 23-20** (4 bits): **TARGET ID**
  - `0-11` (0x0 to 0xB) = specific target
  - `15` (0xF) = controller itself

- **Bits 19-18** (2 bits): **STATUS**
  - `0x0` = idle
  - `0x1` = hit
  - `0x2` = stuck
  - `0x3` = lost connectivity to target / not found
  - `0x4` = lost connectivity to server

- **Bits 17-16** (2 bits): **RESERVED**

- **Bits 15-0** (16 bits): **RESERVED**

## Implementation Notes

### Processing Order
1. **GENERAL** protocol word is processed FIRST
2. **TARGET** protocol word(s) processed THIRD (at minimum)
3. **LIGHTING** protocol uses 3 consecutive words

### Key Constraints
- **12 targets total** (IDs 0-11)
- **8960 total addressable LEDs** (512 LEDs per target, split across targets 0-511, 512-1023, etc.)
- All protocols use **big-endian bit ordering** (MSB first)
- Serial communication for all protocol exchanges

### Bit Extraction Examples
```cpp
// Extract Protocol ID (bits 31-28)
uint8_t protocolId = (word >> 28) & 0x0F;

// Extract Mode (bits 27-24)
uint8_t mode = (word >> 24) & 0x0F;

// Extract Target ID (bits 23-20)
uint8_t targetId = (word >> 20) & 0x0F;

// Extract 8-bit value (e.g., brightness at bits 79-72 in word 1)
uint8_t brightness = (word1 >> 8) & 0xFF;

// Extract 2-bit value (e.g., movement speed at bits 19-18)
uint8_t speed = (word >> 18) & 0x03;
```

### Building Protocol Words
```cpp
// Build RETURN protocol word
uint32_t buildReturnWord(uint8_t mode, uint8_t targetId, uint8_t status) {
    uint32_t word = 0;
    word |= (0x6 << 28);              // Protocol ID = 0x6 (return)
    word |= (mode << 24);              // Mode
    word |= (targetId << 20);          // Target ID
    word |= (status << 18);            // Status
    return word;
}
```

### When Coding
- Always validate protocol ID before processing
- Check target ID bounds (0-11 for targets, special values for all/controller)
- Handle reserved bits (ignore on read, set to 0 on write)
- Implement timeout for serial communication
- Add error handling for malformed protocol words
